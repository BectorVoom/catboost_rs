The kernel body (the actual Green):

```rust
if ABSOLUTE_POS == 0 {
    let pr = prior[0];
    let n = bins.len();
    let k = counts.len();
    // PASS 1 — tally the WHOLE set (no read-before-increment).
    let mut i = 0usize;
    while i < n { let b = bins[i] as usize; counts[b] = counts[b] + 1u32; i += 1usize; }
    // PASS 2 — the CONSTANT denominator: max_b totals[b] (`counterCTRDenominator`).
    let mut m = 0u32;
    let mut j = 0usize;
    while j < k { let c = counts[j]; if c > m { m = c; } j += 1usize; }
    // PASS 3 — map.
    let mut d = 0usize;
    while d < n {
        let b = bins[d] as usize;
        let t = counts[b];
        good[d] = t;
        total[d] = m;                     // mirrors `denoms = vec![denominator; n]`
        value[d] = (F::cast_from(t) + pr) / (F::cast_from(m) + F::from_int(1));
        d += 1usize;
    }
}
```

Host guards (the "typed error, never a semantically-wrong silent fallback" rule):

* `bins.len() != n` ⇒ `CbError::LengthMismatch`;
* any `bin >= bucket_count` ⇒ `CbError::OutOfRange` (the kernel indexes `counts[bucket]`);
* `n == 0` short-circuits to three empty handles;
* wgpu ⇒ `wgpu_reject()` (WR-02), same placement as `launch_ordered_ctr_resident`.

The `counts` scratch is **freshly allocated pre-zeroed per call**
(`client.create(vec![0u32; bucket_count.max(1)])`) and never shared — the task's named risk
(a reused non-zeroed buffer silently doubling the tally) is structurally excluded, and the
in-source comment says so.

  `f64` because the CTR seam is f64 end to end (WR-02) and `binarize_ctr_kernel` binarizes at

* Every device index derives from a host-validated bound: `bins[i]` is range-checked against

## 6. Deviations from the task text

1. **The Red names the two host-readback seams, not `launch_counter_ctr_resident`.** Same
   failure class (missing device path, compile error); the difference is that the oracle goes
   through `compute_counter_ctr_host` / `binarize_counter_column_host`, which is the shipped
   convention for this file (client construction and read-back are production code, never test
   code). Verbatim text in §2.
2. **Two host-readback seams were created, which the task text does not enumerate.** The task
   lists only `launch_counter_ctr_resident`. Test A needs both the `(good, total, value)` triple
   **and** the bit-exact binarized column, and the file's existing shape provides exactly one
   wrapper per purpose (`compute_ordered_ctr_host*` and `binarize_ctr_column_host`). Mirroring
   that gives two symbols rather than one. Both are `#[allow(dead_code)]` with the existing
   source/test-separation comment.
3. **`F::from_int(1)` instead of the task pseudo-code's `+ 1.0`.** Forced by
   `float_literal_f32_fallback` under a generic `F` (§3), and semantically the better spelling of
   `calc_ctr_online`'s hard integer `+1`.
4. **`counts` is `bucket_count` long, not `2 * bucket_count`.** Counter has no class dimension —
   the ordered kernel's `2 *` is the `[N0, N1]` pair. Stated for the reader who diffs the two
   launchers.

No other deviation. The three-pass structure, the serial unit-0 shape, `total[d] = m`, the
`Array<u32>` tally, the host-side bin guard, the `wgpu_reject()`, the `n == 0` short-circuit, the
`synth_fixture(96, 5, 11)` fixture, the two test names and the "do not wire it into
`build_ctr_cindex_columns` / `ctr_covered` / the gate" boundary are all exactly as specified.
