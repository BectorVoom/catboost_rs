## Deviations from the plan

1. **Mutation failure message differs from the plan's prediction (cosmetic, no impact).**
   T03 predicted `left: (0.0, 2.0)`. The observed value is **`left: (-0.0, 2.0)`**.
   Reason: `shift = -left = -min(0.0, p)`, so at `p = 0.0` the shift is **negative zero**,
   and `Debug` for `f64` prints the sign of `-0.0`. The unmutated assertion is still
   exactly green because `PartialEq` for `f64` gives `-0.0 == 0.0`. This is why the test
   uses `assert_eq!` (IEEE `==`) rather than a `to_bits()` comparison: a literal bit
   comparison would fail on the *unmutated* code at `p ∈ {0.0, 0.25, 0.5, 1.0}` for the
   shift component. "Exact, not epsilon" is honoured; "bit equality" is honoured in the
   sense the task intends (no tolerance), not as `f64::to_bits`.
