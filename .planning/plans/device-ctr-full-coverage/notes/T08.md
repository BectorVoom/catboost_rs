## 6. Deviations from the task text

1. **Two extra sub-conjuncts in the host guard.** The task names only
   `target_border_idx <= 1`. A `ctr_type` admission check (`{Borders, Buckets}` only) was added
   alongside it, because the alternative — accepting `Counter`/`BTMV` and falling through to the
   Borders numerator — is precisely the "semantically-wrong silent fallback" the rules forbid.
   Second test `out_of_range_ctr_mode_is_rejected` covers both. **T11/T12/T14/T16 must know
   about this guard** — see §7.
2. **`compute_ordered_ctr_host` kept its signature** and delegates to the new
   `compute_ordered_ctr_host_mode`, rather than growing the two parameters directly. This leaves
   the 4 pre-existing device call sites in the oracle **source-unchanged**, which is stronger
   D-04 evidence than "still passes". `cpu_ordered_ctr` (test-side) *was* extended directly, as
   the task specifies.
3. **`Borders@1` is pinned by the `let mut g = 0u32` initializer, not by an explicit
   `else { g = 0u32; }` arm.** The plan's literal form compiles and passes, but emits
   `warning: value assigned to 'g' is never read` (the initializer becomes dead when all four
   arms assign). Semantically identical, zero new warnings, and the CubeCL manual's
   default-plus-assign pattern is preserved. The unreachability comment sits in the same place.
