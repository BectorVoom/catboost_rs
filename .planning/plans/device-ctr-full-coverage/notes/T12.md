## 4. The prior, pinned on BOTH sides (T06's finding, acted on)

T06 measured that on `ctr_device_counter`'s data the Counter prior is **prediction-neutral
upstream** — `Prior=0.5`, the default `0/1` and `Prior=3` give **bit-identical** predictions,
because upstream compensates by shifting the CTR border (8.999999 at prior 0.5 and 0, 3.999999
at prior 3) and with 16 CTR buckets over integer counts the shifted value never crosses a bin
boundary. **The ≤1e-5 e2e therefore cannot police a Rust-side prior mismatch on this fixture.**

What T12 did about it, three layers, none of which depends on the predictions:

1. **The `BoostParams` pin.** `simple_ctr_priors: vec![0.5]` is set **explicitly** in
   `ctr_params()`, with a doc paragraph on the function and a module-doc section saying why it
   may never be dropped in favour of the default.
2. **An in-test assertion, not just a literal.** `run()` asserts
   `params.simple_ctr_priors == vec![0.5]` before the fit, with the fixture citation in the
   message — so a future edit that "simplifies" the params list fails loudly instead of
   silently training a different recipe.
3. **The structural reason is now executable in-crate.**
   `boosting_ctr_gate_tests::counter_is_a_cpu_legal_whole_set_tally_not_a_class_prefix` pins
   `ECtrType::Counter.default_priors() == [0/1]` against Borders/Buckets' three-prior default,
   mutation-proved in §3.3. That is the fact that makes the omission dangerous, and it is now
   guarded independently of any fixture.

The fixture side is unchanged and untouched: `"simple_ctr": ["Counter:Prior=0.5"]` in the frozen
`config.json`, already asserted by `cb-oracle/tests/ctr_device_counter_fixture_smoke_test.rs`
(re-run green in §5). **`crates/cb-oracle/fixtures/ctr_device_counter/` was never opened for
writing** — `git status --short crates/cb-oracle` is empty.

## 6. Deviations from the task text

1. **`buckets_keeps_the_borders_shape_checks` (T09's test) gained `COUNTER` in its loop.** The
   task text names only the decline→admit move. But C-7 is the invariant "admitting a type
   changes nothing else", and without this one-element addition the newly admitted type would
   ship with its shape checks unpinned — exactly the gap T09's deviation 1 created that test to
   close. One line of loop data + a doc generalisation; mutation-proved (§3.4). The test name
   was deliberately **not** changed (renaming would invalidate T09's note references).
2. **The mixed structure/averaging assertions switched from `COUNTER` to
   `BINARIZED_TARGET_MEAN_VALUE`.** Forced: those two assertions need a type that still
   *declines*, and T12 admits Counter. An in-source note tells T16 to swap again (to an
   out-of-enum stray) rather than delete them.
3. **The e2e asserts `target_border_idx == 0` on every chosen Counter split**, which the task
   does not enumerate. It is free (the loop already walks the splits) and pins
   `target_border_count(Counter, 2) == 1` at the fit level, i.e. that T10's deleted selector
   conjunct stays a no-op on this newly admitted type.
4. **The e2e asserts its own prior pin** (`params.simple_ctr_priors == vec![0.5]`) rather than
   only writing the literal — see §4.2. T06's finding says the pin is the *only* guard, so it is
   made loud rather than left to review.
5. **Five mutations, not the minimum.** MUT-1/2/3 are the mandatory §2.5 set for the two
   green-on-write gate pins plus the row-3 isolation; MUT-4 covers deviation 1; MUT-5 is T20's
   universal check re-run post-Green to prove no residue.
6. **Process slip, recovered and recorded.** After MUT-1 I reverted with
   `git checkout crates/cb-train/src/boosting.rs`, which discarded **all** of T12's `boosting.rs`
   edits, not just the mutation (T10 could safely use that form because it had mutated a file it
   had not otherwise edited). Detected immediately by `grep -n "ECtrType::Counter"` returning
   nothing; the three hunks were reapplied and `git diff crates/cb-train/src/boosting.rs` was
   verified to contain exactly them, then the focused tests re-run green. Every later mutation
   used a targeted textual revert instead. **Rule for later tasks: never `git checkout` a file
   the task itself has edited — revert the mutated span only.**

`run_device_tests.sh` was **not** touched (C-8: T23 owns it); the new binary was verified with an
explicit `--test` invocation. The frozen fixture was never regenerated (§2.6). No BTMV or
