The kernel body (the actual Green):

```rust
if ABSOLUTE_POS == 0 {
    let pr = prior[0];
    let dv = divisor[0];
    let n = perm.len();
    let mut p = 0usize;
    while p < n {
        let doc = perm[p] as usize;
        let bucket = bins[doc] as usize;
        // READ the (Sum, Count) history BEFORE folding this document's own target in.
        let s = sums[bucket];
        let c = cnts[bucket];
        out_sum[doc] = s;
        out_cnt[doc] = c;
        // The ONLY widening point.
        value[doc] = (F::cast_from(s) + pr) / (F::cast_from(c) + F::from_int(1));
        // TCtrMeanHistory::Add — a single running **f32** add. Parity contract; do not widen.
        sums[bucket] = s + (f32::cast_from(class[doc]) / dv);
        cnts[bucket] = c + 1u32;
        p += 1usize;
    }
}
```

Host guards (typed `CbError`, never a semantically-wrong silent fallback):

* `divisor == 0` ⇒ `CbError::OutOfRange` (a device division by zero — see MUT-C's payload);
* `bins`/`class`/`perm` length disagreement ⇒ `CbError::LengthMismatch`;
* any `perm` entry `>= n` ⇒ `CbError::OutOfRange` (**new** relative to the ordered launcher);
* any `bin >= bucket_count` ⇒ `CbError::OutOfRange`;
* any `class > divisor` ⇒ `CbError::OutOfRange` (`targetClass <= targetClassesCount - 1`);
* `n == 0` short-circuits to three empty handles; wgpu ⇒ `wgpu_reject()` (WR-02).

`sums`/`cnts` are **freshly allocated pre-zeroed per call** and never shared.

## 7. Deviations from the task text

1. **The Red names the three host-readback seams, not `launch_btmv_ctr_resident`.** Same failure
   class (missing device path, compile error); the difference is that the oracle goes through
   `compute_btmv_ctr_host` / `read_btmv_sum_bytes` / `binarize_btmv_column_host`, because
   `ComputeClient` construction and buffer read-back live in **production** in this file
   (source/test separation), never in `*_test.rs`. Identical to T11's deviation 1.
2. **A FOURTH test, `btmv_out_of_range_inputs_are_rejected`, and two guards the task text does not
   enumerate.** The task lists `divisor` as a parameter but no validation for it. A zero divisor is
   a device division by zero yielding a NaN column that binarizes to bin 0 everywhere (MUT-C's
   payload), and a class above `targetBorderCount` puts the CTR outside `[0, 1]` (MUT-D's payload)
   — both are "semantically-wrong silent fallbacks", which §2.3 forbids. This mirrors T08's
   deviation 1 exactly (it added `out_of_range_ctr_mode_is_rejected` for the same reason). Both
   conjuncts are mutation-proved.
3. **`launch_btmv_ctr_resident` also validates the PERMUTATION range** (`perm[p] < n`), which
   `launch_ordered_ctr_resident` does not. The kernel indexes `bins[perm[p]]` and `class[perm[p]]`,
   so an out-of-range entry is UB. The pre-existing gap in the ordered launcher was **not**
   touched (out of scope, and no caller can reach it), but the new code does not reproduce it.
4. **`divisor` is `u32` on the host, `Array<f32>` on the seam** (the task text gives it no host
   type). `targetBorderCount = targetClassesCount - 1` is always a small integer, so `u32` makes
   the `class <= divisor` guard exact and the cast to f32 lossless; the kernel parameter is
   `&Array<f32>` exactly as specified, because the addend is computed in the accumulator's own
   width (`class as f32 / divisor` on the CPU, `online.rs:321`/`:351`).
5. **The scratch is TWO arrays (`sums: f32`, `cnts: u32`), not one** — a `TCtrMeanHistory` has two
   fields of different widths and CubeCL has no struct-of-arrays buffer here. The task's pseudo-code
   already names them separately; stated for the reader who diffs the three launchers.
6. **Test C's fixture is `synth_fixture(128, 5, 7)`** (the Buckets oracle's fixture), chosen because
   it satisfies the ≥3-documents-per-bucket guard and yields ≥3 distinct cindex bins. The task text
   does not pin test C's size.
7. **No `CTR_TYPE_BTMV` const was added.** T16 owns the wiring hunk and should add it beside
   `CTR_TYPE_BORDERS`/`_BUCKETS`/`_COUNTER` with the same C-3 citation (see §8).
8. **No git write command was run** (`git add` / `git commit` / anything else).

Everything else is exactly as specified: the honest-accumulator design (option b, not the Borders
alias), no new quantize kernel, `binarize_ctr_kernel` and the border table reused unchanged, the
serial unit-0 shape, the pre-zeroed scratch, the `n == 0` short-circuit, the wgpu rejection, the
three specified test names, and the "do not wire it into `build_ctr_cindex_columns` or the gate"
boundary.
