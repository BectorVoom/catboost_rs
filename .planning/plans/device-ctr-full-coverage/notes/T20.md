### Deliberate placement of the new assertion (deviation-adjacent; read this)

The device-commit assertion is placed **after** the ≤1e-5 comparison loop and its
`max |Δpred|` println, not immediately after the fit. This is intentional and
documented in-source: it is what let the §2.5 mutation check observe **in a single
run** that the prediction bar still passes while the device-commit assertion fails.
Fail-fast ordering would have hidden exactly the evidence DCTR-19's completion
criterion demands. The alternative (assert early) is a one-line move if a later task
prefers it, but it would cost that evidence.

Conventions §2.2 were already satisfied by this file and are preserved: the
`#![allow(clippy::…)]` header, everything device-touching inside
`#[cfg(any(feature = "rocm", feature = "cuda"))] mod device`, no
`use cb_backend::CpuBackend`, and the cpu/wgpu arm SKIPs by printing. The
structure-vs-averaging permutation divergence guard (`assert_ne!`) is untouched.
Source/test separation: unaffected — this is a `tests/` integration target.
