## 2. The `bucket_counts` fallback: FOLD ALL MEMBERS was taken, not the typed error

The task offers two options and says the typed `CbError::Degenerate` "is acceptable and is the
cheaper, honest choice" because *"the branch is unreachable in practice today"*.

**That premise is true of production and false of the committed test corpus, so the typed error
was NOT taken.** `DeviceCtrColumn::default()` gives `bucket_count == 0`, and **six** committed
test literals build their columns with `..DeviceCtrColumn::default()` — including
`session_depth_gt1_test.rs:630`, the genuine **2-member combination**. A typed error there
would have turned `session_ctr_augments_resident_cindex` red at its
`.expect("begin must not error building the CTR-augmented resident session")`, i.e. it would
have been a behaviour change smuggled in under "unreachable".

What landed instead:

```rust
if col.bucket_count > 0            { Ok(col.bucket_count) }                    // production
else if col.member_bins.len() <= 1 { Ok(<BTreeSet distinct count>) }           // byte-unchanged
else { combine_projection_bins(&col.member_bins, n).map(|(_, b)| b.max(1)) }   // NEW
```

* the single-member arm is **byte-unchanged** (D-04);
* the combination arm folds **all** members through the *same* `combine_projection_bins`
  identity `build_ctr_cindex_columns` uses forty lines below, so the count is the projection's
  real distinct-bucket count **by construction**, not by a second transcription;
* `.collect()` became `.collect::<CbResult<Vec<usize>>>()?` — the only signature ripple.

The false clause *"(single-member columns; the gate admits only simple projections)"* was
**deleted, not amended**, and replaced by a comment stating the new truth: combination columns
can reach here, and taking member 0's cardinality under-counts the projection, which **inflates
every other column's `cat_feature_weight`** — a silent wrong answer, not merely a worse one.
