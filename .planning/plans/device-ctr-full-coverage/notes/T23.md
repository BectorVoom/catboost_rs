## 1. The final gate form

```rust
fn ctr_types_are_device_covered(cols: &[crate::ctr::CtrFeatureColumn]) -> bool {
    !cols.is_empty()
        && cols.iter().all(|col| {
            // DCTR-18 (T23): the FINAL form. … (22 lines of in-source rationale: C-3, why
            // `from_i8` makes an unknown discriminant decline BY DEFAULT, and why enumerating
            // the four types here would be a SECOND list that can drift from

}
```

`device_host_eligible` / `ctr_covered` clauses with each one's owning negative test and its

otherwise for each clause. The stale sentence *"which is why the admission list is an explicit

## 4. What happened to T00's gate-state table

**Retired into its final form, not deleted.** The task's completion criterion is explicit that
shipping the collapse without this would leave a table whose comments promise flips that already
happened. Concretely, in `device_ctr_combo_config_test.rs`:

* **`GateRow.flips_at` is DELETED** and replaced by `permanent: bool`. All ten forward promises
  are discharged (T01 row 6, T10 rows 4/9/10, T12 row 3, T16 row 5, T19 row 2), so the field's
  entire content had become a record of the past wearing the grammar of the future.
* **A single header replaces them**, at the top of the table's doc block, stating: P1 is
  complete and every expectation is final; **P2/P3 will ADD rows, not flip these** — with the
  reason, which is load-bearing rather than rhetorical: the four exclusions those phases lift
  (`learning_folds_for_cycle`, `eval_sets`, `has_any_scorable_feature`, the border-count shape
  check) are **not functions of a column's `(arity, ctr_type, target_border_idx, prior_denom)`
  shape**, so none of them *can* move a row of this table; and ⇒ **a mismatch here is now a
  regression, never a wave landing**.
* **Rows 1, 7 and 8 are called out as permanent**, `permanent: true`, and the failure message
  says so per row: row 1 is the D-04 positive pin, rows 7/8 are the GPU-only types which have no
  CPU parity surface for *any* phase.
* The per-row history the `flips_at` notes carried is **preserved** in the ASCII table in the
  doc block (`admitted by T19 (arity conjunct deleted)`, …), so nothing is lost — it is just no
  longer phrased as a licence to change the row.
* Row 4's honest-limitation paragraph and rows 9/10's decomposition argument are **kept**: they
  are still the reason the table can attribute a red to a single conjunct.
* `gate_admits_exactly_the_current_wave` → **renamed** `gate_admits_exactly_the_final_p1_set`
  (there is no "current wave" left). Module-doc clause (d) records the old name; a new clause
  (e) records that the conscious act is complete. **Deviation §6.2.**

**Coverage after retirement**: the table keeps *all* of its coverage — nothing was deleted, and
its ten rows still run on every change to the predicate. What is new is that
`gate_admits_exactly_the_cpu_supported_ctr_types` in `boosting_ctr_gate_test.rs` now covers a
**superset** of the table's type dimension (all six discriminants + five strays + a mixed set +
the empty set, each on a combination projection at `target_border_idx = 1`), so the two are
deliberately redundant on types. They are *not* redundant overall: the table is the only place
that varies `prior_denom`, arity and selector **independently** row by row, which is what lets a
red be attributed to one conjunct (T10's rows 9/10 decomposition). Both were kept for that
reason.
